## 2. Новые подтверждённые факты (сверка с исходниками)

1. **Запрос версии прошивки.** Параметра `AUTOPILOT_VERSION` в 4.7.2 нет.
   Версия читается через `MAV_CMD_REQUEST_AUTOPILOT_CAPABILITIES` = **520**,
   где `param1` обязан равняться 1 (`GCS_Common.cpp:5080-5088`), в ответ
   приходит `MSG_AUTOPILOT_VERSION` (msgid 148). Формат кадра
   `<QQIIIIHH8B8B8B18B` (78 байт); версия упакована как
   `major<<24 | minor<<16 | patch<<8 | fw_type` (`GCS_Common.cpp:3000-3003`).

2. **Перезагрузка.** `MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN` = **246**:
   `param1` = 1 (перезагрузка) / 3 (загрузчик), иначе `UNSUPPORTED`;
   `target_component` должен быть `MAV_COMP_ID_ALL` (0) или `mavlink_system.compid`,
   иначе `DENIED`; при `soft_armed` — `FAILED`, если не подставлено 20190226 в
   `packet.y`; **ACK отправляется до перезагрузки** (`GCS_Common.cpp:3510-3686`).

3. **Тест мотора армит аппарат.** `motor_test.cpp:165-170` ставит
   `motors->armed(true)` и `hal.util->set_soft_armed(true)`;
   `motor_test_stop()` (`motor_test.cpp:201-233`) снимает оба флага. Флаг
   ARMED в heartbeat берётся из `motors->armed()`
   (`GCS_MAVLink_Copter.cpp:52-53`) — **поэтому проверку ARMED надо делать
   по снимку состояния ДО отправки команды теста**.

4. **Официальные схемы подтверждают правило ярусов.** Проверено на двух SVG:
   `m_04_01_octo_quad_x.svg` (верх 1,2,3,4 = A,G,E,C; низ 5,6,7,8 = H,B,D,F) и
   `m_04_14_octo_quad_x_cw.svg` (верх 1,3,5,7 = A,C,E,G; низ 2,4,6,8 = B,D,F,H).
   Правило: коаксиальная пара = два мотора с одинаковым углом; верхним в паре
   считается тот, что раньше в таблице `MotorDef`.

## 3. Аудит приложения против §5/§6/§7 и закрытие пробелов

### §5.8 — модель мотора

Было: `FrameMotor(motor, position, direction, test_order, angle)`.
Стало (`code/motor_mapping_core.py`):

| Поле §5.8 | Имя в коде | Источник |
|---|---|---|
| motorNumber | `motor_number` | номер M1..M8 |
| physicalPosition | `physical_position` | угол → луч (`angle_to_position`) |
| layer | `layer` | `derive_layers()` + официальные SVG |
| rotation | `rotation` | направление из `MotorDef` |
| testOrder | `test_order` | третье число `MotorDef` |
| testButton | `test_button` | буква по номеру теста (A..H) |
| servoFunctionId | `servo_function_id` | 32 + N (`SRV_Channel.h:82`) |
| physicalOutput | `physical_output` | **nullable**, из прочитанных `SERVOx_FUNCTION` (`attach_physical_outputs`) |

### §5.2 / §5.6 — кнопки A–H, блокировка при ARMED

* Кнопки **A…H** запускают тест мотора по номеру **теста** (`param1`), перед
  отправкой показываются место, ярус, номер мотора и буква.
* Тест блокируется, если аппарат **уже** ARMED — проверка идёт по снимку
  состояния до старта (см. факт 3 выше).
* Газ и время ограничены; STOP остаётся отдельной командой.

### §5.3 — проверка версии прошивки

При подключении автоматически запрашивается версия (CMD 520); версия вне
линейки 4.7.x даёт предупреждение.

### §5.4 — запись FRAME_* с перезагрузкой и сверкой

Отдельное действие «Записать FRAME_CLASS/FRAME_TYPE»:
бэкап параметров в `configs/` → запись → readback → останов теста мотора →
ожидание disarm → `CMD 246` → ожидание heartbeat после перезагрузки →
повторное чтение `FRAME_CLASS`/`FRAME_TYPE` → сверка с записанными значениями.

### §5.5 — назначение выходов отдельным действием

Кнопки разведены: «Назначить выходы (SERVOx_FUNCTION)» и «Записать
FRAME_CLASS/FRAME_TYPE». Добавлена диагностика `audit_motor_functions()`:
пропущенные функции 33…40 (WARN) и одна функция на двух выходах (ERROR).

### §5.7 — чек-лист валидации вращения

Ручной чек-лист из 8 строк с прогрессом «X/8 проверено» и результатом
«совпало / не совпало / не проверено».

### §8 — границы профиля

Предупреждения для `FRAME_CLASS=3`, `FRAME_TYPE=0/12/14/20/21`,
`FRAME_CLASS=17`, и отдельно — когда выбранная комбинация не равна профилю
`arducopter-4.7-octaquad-x`.

## 4. Найденные и исправленные ошибки

1. **Декодер версии прошивки был неверен.** Использовался формат
   `<QIIIIBBB` — неверное число полей и смещения. Реальный формат
   `<QQIIIIHH8B8B8B18B`; версия читалась из мусора. Исправлено, покрыто
   тестом.
2. **Пустые раскладки в таблице рам.** Для класса OCTA типы X/DJI_X/CW_X были
   пустыми списками (плата отдавала 0 моторов). Заполнены из
   `AP_MotorsMatrix.cpp:875-963`.
3. **Старые имена полей модели** разъехались с §5.8 — переименовано, потребители
   (GUI, тесты) обновлены.
