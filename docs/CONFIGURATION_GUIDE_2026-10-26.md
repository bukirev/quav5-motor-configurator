## 1. Быстрый итог

- Рама настроена как восьмимоторная коаксиальная: `SYS_AUTOSTART=12001`, `CA_ROTOR_COUNT=8`. Пользователь описал восемь моторов, по два на каждом из четырёх лучей; маркировка платы и фактическая нумерация моторов по проводам ещё не проверены.
- Все восемь MAIN-выходов назначены функциям Motor 1–8 (`PWM_MAIN_FUNC1..8=101..108`). Группы MAIN установлены на PWM 50 Гц. Это подтверждение конфигурации PX4, но не измерение сигнала на разъёмах.
- Снятые ранее значения MAIN для disarmed были 1000, рабочий диапазон задан 1100–1900 мкс. Физический PWM тестером/осциллографом не подтверждён.
- DroneCAN включён для сенсоров, подписки GPS и магнитометра включены. CAN-магнитометр обнаружен и сохранён в калибровочных параметрах. GPS по CAN в последнем потоке MAVLink не обнаружен.
- Конфигурация ожидает GPS (`SYS_HAS_GPS=1`) и использует GPS для внешней навигации в EKF (`EKF2_GPS_CTRL=7`), но live-телеметрия GPS не показала. Это нужно решить до любых режимов/миссий, требующих глобальной позиции.
- В настройках питания стоит 12S и источник Power Module. Реальную батарею, модуль и точность калибровок пользователь не подтверждал.
- В конфигурации присутствуют значения circuit-breaker, которые по справочнику PX4 отключают проверки IO safety, USB-link и flight termination. Не менять их в ходе диагностики; до эксплуатации выяснить, почему они установлены, и сверить с версией прошивки и требованиями платы.

## 2. Аппарат, тип рамы и геометрия

| Параметр | Значение | Что означает / что проверить |
|---|---:|---|
| `MAV_TYPE` | 14 | Тип аппарата в параметрах — Octocopter. |
| `SYS_AUTOSTART` | 12001 | Профиль Generic 10-inch Octo Coaxial. Название профиля не доказывает, что фактические винты именно 10 дюймов. |
| `SYS_AUTOCONFIG` | 0 | Автоматическую перенастройку по airframe сейчас не запускать. |
| `CA_AIRFRAME` | 0 | Multirotor. |
| `CA_ROTOR_COUNT` | 8 | В геометрии PX4 настроено восемь роторов. |

Записанные позиции `CA_ROTOR0..7` образуют четыре совпадающих по X/Y пары в двух плоскостях; `Z=-0.05` и `Z=+0.05`. У каждой пары знаки `CA_ROTOR*_KM` противоположны, что задаёт противоположный знак реактивного момента. Значения X/Y равны `±0.35`. Это геометрические коэффициенты airframe, а не надёжное доказательство, к какому именно физическому проводу MAIN1–8 подключён каждый мотор.

До полёта сопоставить схему airframe в QGroundControl с физической нумерацией и направлением вращения всех восьми моторов. Пользователь ранее сказал, что пропеллеры сняты; проверить их снятие перед любым новым тестом.

## 3. MAIN M1–M8 и ESC

Все восемь каналов имеют назначения `Motor 1`…`Motor 8`: `PWM_MAIN_FUNC1=101` … `PWM_MAIN_FUNC8=108`.

| MAIN | Функция PX4 | Disarmed | Min | Max | Failsafe override |
|---:|---|---:|---:|---:|---:|
| 1–8 | Motor 1–8 (101–108) | 1000 мкс | 1100 мкс | 1900 мкс | -1 (значение берётся по умолчанию для функции) |

- `PWM_MAIN_TIM0=50`: MAIN1–2; `PWM_MAIN_TIM1=50`: MAIN3–4; `PWM_MAIN_TIM2=50`: MAIN5–8. В PX4 это выбор PWM rate, требуется reboot для применения параметров таймерной группы. Период 50 Гц равен 20 мс.
- `PWM_MAIN_REV=0`: реверс диапазона для MAIN не задан.
- После первоначального назначения функций телеметрия `SERVO_OUTPUT_RAW` показывала 1000 на всех MAIN при disarmed. По просьбе пользователя отдельно выполнялись краткие actuator tests с вычисленным уровнем 1200; после одной серии telemetry показывала 1000, после повторной серии на короткое время пропала связь. На физических M1–M8 форма/ширина сигнала не измерялась.
- Модель ESC и поддерживаемые им протоколы неизвестны. Перед дальнейшими изменениями проверить документацию ESC и в QGroundControl точный протокол выходов. Настройка PWM 50 Гц не гарантирует, что ESC принимает PWM или что на разъёме есть импульс.
- Проверка физического выхода: только с пропеллерами снятыми, коротко по одному каналу, между Signal и GND осциллографом/логическим анализатором. Число в MAVLink не заменяет измерение контакта.
- Расчёт уровня `.125` для 1200 мкс был выполнен по формуле `(1200-1100)/(1900-1100)`. Не использовать этот коэффициент повторно без проверки семантики `MAV_CMD_ACTUATOR_TEST` для фактической версии PX4: это была расчётная команда, не доказательство реального импульса 1200 мкс.

## 4. GPS, компас и DroneCAN

| Параметр | Значение | Интерпретация |
|---|---:|---|
| `UAVCAN_ENABLE` | 2 | DroneCAN включён для сенсоров; DNA server включён. |
| `UAVCAN_BITRATE` | 1000000 | Номинальная скорость CAN 1 Мбит/с; проверить совместимость всех узлов. |
| `UAVCAN_NODE_ID` | 1 | Node ID самого PX4. |
| `UAVCAN_SUB_GPS` | 1 | Подписка PX4 на GPS по DroneCAN включена. |
| `UAVCAN_SUB_GPS_R` | 1 | Включена подписка относительного GNSS сообщения, если узел/сборка его поддерживает. |
| `UAVCAN_SUB_MAG` | 1 | Подписка на магнитометр по DroneCAN включена. |
| `UAVCAN_SUB_*` прочие | 0 | Остальные перечисленные датчиковые подписки (baro, battery, airspeed и др.) выключены. |

**Компас:**

- `CAL_MAG0_ID=396825`, `CAL_MAG0_PRIO=50`.
- `CAL_MAG1_ID=8944899` (`0x887D03`), `CAL_MAG1_PRIO=75`. Старший байт `0x88` соответствует UAVCAN magnetometer device type в PX4; адресный байт `0x7D` указывает на CAN node 125. Это подтверждает обнаруженную PX4 запись CAN-магнитометра, но не физический осмотр кабеля, направление установки или качество калибровки.
- `SENS_MAG_MODE=1`: публикуется primary magnetometer (по справочнику PX4). `EKF2_MAG_TYPE=0`: автоматический режим магнитометра. Нужно проверить выбранный primary в Vehicle Setup → Sensors, ориентацию корпуса и калибровку на реальном аппарате.
- В `HIGHRES_IMU` в прошлой успешной сессии были ненулевые магнитные значения. По одному `HIGHRES_IMU` нельзя определить, какой из двух магнитометров дал измерения.

**GPS:**

- `GPS_1_CONFIG=201` — порт GPS1 UART, а не CAN-подключение. `GPS_1_PROTOCOL=1` — u-blox для этого последовательного порта. `GPS_2_CONFIG=0` — второй serial GPS порт выключен.
- Отдельно для CAN GPS настроены `UAVCAN_ENABLE=2` и `UAVCAN_SUB_GPS=1`, но в проверенной MAVLink-телеметрии не было `GPS_RAW_INT` или `GPS2_RAW`; бит присутствия GPS отсутствовал в `SYS_STATUS.onboard_control_sensors_present`.
- `SYS_HAS_GPS=1` означает, что конфигурация считает GPS ожидаемым/доступным для проверок; это не доказательство, что GPS сейчас обнаружен.
- `EKF2_GPS_CTRL=7`: включены GNSS lon/lat, altitude и 3D velocity fusion; bit3 dual-antenna heading не включён. Пока GPS фактически не обнаружен, этот параметр сам по себе не создаёт GPS-данные.
- Следующий шаг: точная модель CAN-GPS, питание и совместимость протокола, список DroneCAN nodes в QGC, `uavcan status` в MAVLink Shell (если доступен), сообщения `GPS_RAW_INT` и fix_type/satellites. Не менять `GPS_1_CONFIG` наугад.

## 5. IMU, барометр и EKF

- В снимке есть несколько калибровочных записей акселерометра и гироскопа (`CAL_ACC*`, `CAL_GYRO*`); для нескольких датчиков указаны ID и offsets. Присутствие calibration parameters не гарантирует точную текущую калибровку или правильное крепление платы.
- `SYS_HAS_BARO=1`; `EKF2_EN=1`; `EKF2_BARO_CTRL=1` — EKF2 включён и барометр включён как источник высоты согласно параметрам.
- `EKF2_DECL_TYPE=3` — тип магнитного склонения требует сверки с фактической версией и источником курса; не менять без проверки GPS/компаса.
- До калибровки подтвердить, что FC жёстко закреплён правильной стороной, измерения неподвижного аппарата стабильны, GPS/компас не окружены магнитными помехами. Не запускать калибровку без прямой просьбы пользователя и сохранения исходных параметров.

## 7. Failsafe и arming checks — критичная часть

| Параметр | Значение | Комментарий |
|---|---:|---|
| `COM_RC_LOSS_T` | 0.5 с | Время до признания потери ручного управления, согласно конфигурации. |
| `NAV_RCL_ACT` | 2 | Return при RC/manual-control loss по справочнику PX4. Фактическая возможность Return зависит от GPS/домашней позиции. |
| `COM_DL_LOSS_T` | 10 с | Таймаут GCS/data-link loss. |
| `NAV_DLL_ACT` | 0 | Data-link-loss action отключён. |
| `COM_OF_LOSS_T` | 1 с | Таймаут потери Offboard (сама реакция зависит от связанной конфигурации). |
| `COM_ARM_WO_GPS` | 1 | Документация PX4 описывает это как warning-only для GPS preflight check; отсутствие позиции всё равно ограничивает режимы, которым нужна глобальная позиция. Не означает, что GPS исправен. |
| `COM_ARM_CHK_ESCS` | 0 | Проверка статуса/ошибок телеметрических ESC отключена; эта проверка применима к ESC, передающим телеметрию. |
| `COM_ARM_MAG_STR` | 2 | Режим магнитных preflight checks; не менять без точного описания установленной версии. |

**Значения circuit-breaker в живом снимке:**

- `CBRK_IO_SAFETY=22027` — магическое значение, которое в PX4 reference отключает IO safety.
- `CBRK_USB_CHK=197848` — значение, которое отключает USB-connected checks.
- `CBRK_FLIGHTTERM=121212` — значение, которое отключает Flight Termination action.
- `CBRK_SUPPLY_CHK=0`, `CBRK_BUZZER=0`, `CBRK_VTOLARMING=0`.

Эти три значения с отключающими эффектами уже присутствовали в скачанной конфигурации; в рамках этой выгрузки они не менялись. Это не рекомендация оставлять или менять их. До любого полётного применения выяснить их причину, проверить точную модель V5+ и актуальный PX4 reference, физический safety switch и метод питания. Не менять circuit-breakers экспериментально.

В числе считанных значений: `MPC_THR_HOVER=0.5`, `MPC_THR_MIN≈0.12`, `MPC_THR_MAX=1`, `MPC_XY_VEL_MAX=12 м/с`, `MPC_Z_VEL_MAX_UP=3 м/с`, `MPC_Z_VEL_MAX_DN=1.5 м/с`, `MPC_MAN_TILT_MAX=35°`, `MPC_TKO_SPEED=1.5 м/с`, `MPC_LAND_SPEED≈0.7 м/с`.

## 10. Связь и интерфейсы

- Heartbeat пришёл с `system=1`, `component=1`, `vehicle_type=14` (Octocopter), `autopilot=12` (PX4). Это идентифицирует поток протокола, но не точную модель платы или firmware version.
- `MAV_0_CONFIG=101` — одна из serial-функций MAVLink назначена на TELEM1; подключённый COM18 по USB — отдельный интерфейс, не обязательно TELEM1.
- `MAV_SYS_ID=1`, `MAV_COMP_ID=1`, `MAV_PROTO_VER=2`.
- `AUTOPILOT_VERSION` запрашивался, но ответа не получено; версию/build и target платы записать в следующий раз через QGC Firmware/Vehicle Summary или корректный version request.
- COM18 несколько раз был доступен без входящих байтов. При любом будущем чтении сначала проверить heartbeat и свежесть сообщений, а затем уже делать выводы по параметрам.

## 11. План безопасной проверки перед следующей настройкой

1. Сверить маркировку контроллера, PX4 version/build, модель GPS/компаса, ESC, батарею/Power Module и физическую распиновку.
2. Сохранить новый full parameter snapshot перед каждой серией изменений. Сравнивать снимки diff-ом, не загружать старый `.params` вслепую.
3. Проверить heartbeat, MAVLink сообщения, состояние armed/disarmed, GPS/MAG Sensor status и DroneCAN node list.
4. Для CAN GPS проверить питание, CAN_H/CAN_L, общую CAN шину, совместимость DroneCAN firmware, termination и факт появления GPS telemetry/fix; параметры CAN узла читать отдельно в QGC component.
5. Для MAIN: сверить Motor 1–8 в Actuator Configuration с реальными ESC и схемой рамы; уточнить ESC protocol; при снятых пропеллерах измерить PWM сигнал между Signal и GND на каждом канале. Не использовать двигатель/пропеллер как способ проверки сигнала.
6. Проверить `BAT1_*` по фактической батарее и Power Module; проверить, почему circuit-breakers отключают IO safety, USB check и flight termination.
7. Только после проверки конфигурации и датчиков проводить калибровки/выходные тесты с прямой просьбы пользователя и записывать точные условия/результат.
