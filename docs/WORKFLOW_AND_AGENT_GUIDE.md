**Проект:** QUAV/CUAV V5+ с PX4, каталог `C:\Trading\!!!px4`  
**Дата записи:** 2026-10-26  
**Проверено на устройстве:** COM18, MAVLink через USB  
**Ограничение:** точная маркировка платы, версия/build PX4, версия QGroundControl, модель CAN-GPS/компаса и модель ESC не установлены. Сведения, сообщённые пользователем, помечены отдельно от измерений.

## 1. Краткий статус на момент последней успешной проверки

- Пользователь сообщил: восемь моторов, по два на каждом из четырёх лучей; ESC подключены к MAIN M1–M8; пропеллеры сняты. Пользователь не сообщил точную модель ESC.
- PX4 heartbeat ранее показывал тип Octocopter. Считаны `SYS_AUTOSTART=12001` (Generic 10-inch Octo coaxial), `CA_ROTOR_COUNT=8`; роторная геометрия была коаксиальная с парными верхним/нижним моторами. Это совпадает с описанной пользователем компоновкой, но физический порядок моторов требуется сверять по схеме рамы.
- `PWM_MAIN_FUNC1..8` назначены на Motor 1..8 (значения 101..108); при disarmed телеметрия показывала по 1000 на каналах 1–8. Физический импульс на разъёмах не измерялся.
- Таймерные группы MAIN переведены с 400 на 50 Гц и после перезагрузки параметры `PWM_MAIN_TIM0..2=50` подтвердились. Поддержку 50 Гц конкретными ESC не проверяли.
- Короткие тесты ACTUATOR_TEST на вычисленный уровень 1200 мкс проводились по просьбе пользователя. На разъёмах осциллографом/логическим анализатором ширина импульса не проверена. При повторной серии телеметрия пропала, поэтому именно конечное состояние после этой серии подтвердить не удалось.
- На последней успешной проверке DroneCAN включён: `UAVCAN_ENABLE=2`, `UAVCAN_SUB_GPS=1`, `UAVCAN_SUB_MAG=1`.
- В параметрах найден внешний CAN-магнитометр `CAL_MAG1_ID=8944899` (`0x887D03`) с приоритетом 75; второй магнитометр имел `CAL_MAG0_ID=396825`, приоритет 50. В `HIGHRES_IMU` поступали ненулевые магнитные значения. Это подтверждает, что PX4 видит магнитометр UAVCAN; не считать это осмотром разъёма или подтверждением качества калибровки.
- `GPS_1_CONFIG=201` и `GPS_1_PROTOCOL=1`: GPS1 serial-порт и протокол u-blox. `GPS_1_CONFIG` не выбирает CAN GPS. Несмотря на `UAVCAN_SUB_GPS=1`, в проверенных потоках не было `GPS_RAW_INT`/`GPS2_RAW`, а флаг GPS отсутствовал в `SYS_STATUS.onboard_control_sensors_present`. CAN GPS на тот момент не подтверждён.
- COM18 несколько раз определялся Windows, но не передавал байты; позже поток MAVLink восстановился. Само наличие COM-порта не считать связью или доказательством исправности датчиков.

Подробная хронология действий и результатов остаётся в [журнале сессии](../logs/2026-10-26-no-motor-output.md).

## 2. Хронология выполненных действий

1. Создан проект `C:\Trading\!!!px4` с `AGENTS.md`, README, разделами `code/`, `docs/`, `logs/`.
2. Пользователь сообщил об отсутствии сигналов управления на восьми ESC; ESC пищали как при отсутствии сигнала. Затем уточнил, что ESC стоят на MAIN M1–M8, аппарат имеет восемь моторов (по два на луч), пропеллеры сняты. Проверку уровня сигнала прибором пользователь не описал.
3. При первом чтении COM18 получен MAVLink heartbeat PX4, Octocopter; состояние было disarmed. Считаны параметры: `PWM_MAIN_FUNC1..8=0`, `PWM_AUX_FUNC1..11=0`, MAIN DIS=1000, MIN=1100, MAX=1900, `SYS_AUTOSTART=12001`, `CA_ROTOR_COUNT=8`, частоты трёх групп 400 Гц.
4. После подтверждения геометрии назначены `PWM_MAIN_FUNC1..8=101..108` (Motor 1..8). Повторное чтение подтвердило назначения. В disarmed `SERVO_OUTPUT_RAW` выдавал 1000 на MAIN1–8. Это телеметрические значения PX4, а не измерение формы сигнала на контактах.
5. По просьбе пользователя `PWM_MAIN_TIM0`, `PWM_MAIN_TIM1`, `PWM_MAIN_TIM2` изменены с 400 на 50 Гц. Перед reboot heartbeat был disarmed. Отправлена команда перезагрузки PX4, не bootloader. После reboot heartbeat восстановился; значения 50/50/50 прочитаны повторно.
6. По прямой просьбе пользователя выполнен тест уровня, рассчитанного как 1200 мкс: при MIN=1100/MAX=1900 использована нормализация `(1200-1100)/(1900-1100)=0.125`. Для M1..M8 по очереди отправлено по 10 обновлений `MAV_CMD_ACTUATOR_TEST`, затем каждому каналу — stop. Аппарат не армировали. После теста получены disarmed heartbeat и телеметрические 1000 на восьми каналах. Физический импульс 1200 мкс не измерялся.
7. По просьбе пользователя тест повторён: по три обновления на каждый M1..M8, затем stop для каждого выхода и общая остановка. Следующий опрос не получил ACK, heartbeat или `SERVO_OUTPUT_RAW`; на COM18 было 0 байт при чтении 115200 и типовых baud. Поэтому физический выход, успешность тестового уровня и конечное состояние именно после повторной серии не подтверждены. Новые actuator-команды до восстановления чтения не отправлялись.
8. Несколько read-only проверок COM18 также получили 0 байт. В следующей сессии поток восстановился. Параметры читались командами `PARAM_REQUEST_READ`; изменения не выполнялись.
9. При успешном чтении DroneCAN параметры показали `UAVCAN_ENABLE=2`, `UAVCAN_SUB_GPS=1`, `UAVCAN_SUB_MAG=1`. Магнитометр с ID `0x887D03` (тип UAVCAN MAG, адресный байт `0x7D`) зарегистрирован с приоритетом 75; приходили ненулевые данные `HIGHRES_IMU`. GPS-сообщений не было; `SYS_STATUS` не показывал GPS как присутствующий. Значение `GPS_1_CONFIG=201` относится к порту GPS1 UART. Запись внесена в журнал.

## 3. Обязательный рабочий порядок следующего агента

### Перед подключением и любыми изменениями

1. Прочитать этот файл, корневой `AGENTS.md`, `README.md`, документы `docs/` и последние записи `logs/`. Учитывать, что старый статус может измениться; сначала перечитать устройство.
2. Уточнить маркировку платы и точную версию PX4/build, QGroundControl, тип ESC, тип GPS/компаса и используемый протокол/прошивку CAN-узлов. Не выдавать названия QUAV/CUAV V5+ за подтверждённую модель, пока не проверена маркировка.
3. Для любой настройки или теста моторов убедиться, что пропеллеры сняты; сообщённое пользователем состояние перепроверить, когда пользователь рядом с аппаратом. Не армировать и не запускать моторы без прямой просьбы. Держать руки и предметы вдали от моторов.
4. Начать только с чтения. Появление COM18 в диспетчере устройств недостаточно: получить heartbeat, проверить system/component ID и поток сообщений. Если COM18 молчит, не отправлять управляющие команды и не считать чтение параметров успешным; записать baud, длительность, байты и ошибку.
5. Перед записью параметров сохранить исходные значения/полный дамп, назвать конкретные параметры и ожидаемое влияние, получить явную просьбу пользователя на эти изменения. После записи перечитать значения и записать «до → после → основание → проверка». Для reboot отдельно убедиться по heartbeat, что аппарат disarmed.

### Проверка GPS и компаса DroneCAN

1. Считать read-only `UAVCAN_ENABLE`, `UAVCAN_SUB_GPS`, `UAVCAN_SUB_MAG`, GPS/MAG calibration IDs и приоритеты. Не менять их наугад.
2. `UAVCAN_ENABLE=2` включает DroneCAN для датчиков с DNA server; подписки GPS/MAG должны быть включены для соответствующих CAN-сенсоров. Само значение подписки не доказывает, что модуль физически подключён или выдаёт данные.
3. Проверять признаки работающего GPS: heartbeat/сообщения PX4, `GPS_RAW_INT` (fix type, satellites, координаты, возраст данных), `GPS2_RAW` при втором приёмнике, GPS presence/health в `SYS_STATUS`, ошибки/сообщения PX4 и список DroneCAN-узлов/QGC. Отсутствие GPS fix не всегда означает отсутствие CAN-узла; различать «узел найден» и «спутниковый fix получен».
4. Для внешнего компаса смотреть наличие отдельного `CAL_MAGx_ID`, приоритет, статус Sensors в QGC, данные магнитометра и сообщения о калибровке/ошибках. Декодирование Device ID использовать только по формату PX4, сверяя тип шины/устройства; не угадывать по одному числу. Проверять, какой компас реально выбран как primary. Ненулевой `HIGHRES_IMU` подтверждает поток магнитных данных, но сам по себе не доказывает, что данные пришли именно от внешнего компаса.
5. В QGC осмотреть Vehicle Setup → Sensors и DroneCAN/CAN node parameters (могут отображаться отдельными компонентами). Если доступен PX4 MAVLink Shell, команда `uavcan status` предназначена для просмотра статуса CAN; выполнять только как чтение и сохранять вывод.
6. Физическую проводку проверять по руководству конкретного GPS/CAN-модуля и маркировке платы: разъём CAN, CAN_H/CAN_L, GND, допустимое питание, непрерывность шины, цепочка устройств и терминаторы на концах. CAN-устройства обычно работают на общей шине; не подключать каждый узел как отдельную UART-линию. Ничего не переставлять под питанием.
7. `GPS_1_CONFIG=201` — выбор GPS1 serial-порта в PX4; не менять его, чтобы «включить CAN». Для DroneCAN GPS проверять `UAVCAN_ENABLE` и `UAVCAN_SUB_GPS`, затем обнаружение узла и сообщения. Перед изменением параметров найти точное описание для фактической версии прошивки.
8. Калибровку компаса выполнять только по просьбе пользователя и после подтверждения подходящего места вдали от металла/магнитных помех; сначала записать исходные IDs/приоритеты и точно следовать подсказкам QGC. Не калибровать при неустойчивой связи.

### Проверка MAIN M1–M8

1. Сначала перечитать `PWM_MAIN_FUNC1..8`, `PWM_MAIN_MIN1..8`, `PWM_MAIN_MAX1..8`, `PWM_MAIN_DIS1..8`, timer groups и актуальные actuator output protocol параметры. Сверить версию PX4 и возможности конкретного ESC; не считать PWM/DShot взаимозаменяемыми.
2. В текущей конфигурации записаны функции Motor 1..8 (101..108), диапазон MIN=1100/MAX=1900 и таймеры MAIN 50 Гц. 50 Гц означает период 20 мс. Не повышать частоту и не менять протокол без документации ESC и явной просьбы.
3. Число/геометрию и выходной порядок сверять с frame setup и реальными проводами. Рама `SYS_AUTOSTART=12001` была признана согласующейся с восьмимоторной coaxial-схемой только на основании сообщения пользователя о двух моторах на каждом из четырёх лучей; перепроверять расположение и направление вращения по сборочной схеме.
4. Тест выхода физически может запустить ESC/мотор. Только с пропеллерами снятыми, каждый мотор по одному, короткий тест, затем явный stop. Не армировать аппарат для проверки PWM. Не считать отправку команды равной наличию сигнала на контакте.
5. Расчёт `.125` для 1200 мкс в этой сессии был линейно выведен из MIN=1100/MAX=1900. Это не универсальная конвертация: перед повторным использованием проверить семантику actuator test для фактической версии PX4 и потока. Подтверждение на разъёме требует осциллографа/логического анализатора между Signal и GND; одновременно записать частоту, ширину импульса и канал.
6. При пропаже телеметрии после теста не запускать следующую серию. Сначала восстановить heartbeat и перечитать disarmed/outputs. Если связь не восстановлена — явно записать неопределённость конечного состояния.
7. Если PWM численно виден в MAVLink, а измерения на MAIN нет, проверить правильный контакт Signal/GND, ориентацию разъёма, IO/servo rail и аппаратную схему по официальному руководству CUAV; не заявлять, что PWM на разъёме подтверждён.

## 4. Как документировать работу

- После каждой сессии добавить датированный раздел в `logs/`, не перезаписывая старые записи и дампы.
- Указывать: что пользователь сообщил; что прочитано из PX4; какие именно команды/параметры применены; было ли подтверждение ACK/readback; состояние disarmed; параметры времени/порта; что измерено физически; что осталось неизвестным.
- Разделять статусы: **прочитано на устройстве**, **сообщено пользователем**, **выведено по косвенным признакам**, **не проверено физически**.
- Не записывать сырые серийные номера/логи, если они не нужны; не сохранять секреты.
- В финальном отчёте перечислить изменённые файлы, результат проверки, оставшиеся вопросы и следующий безопасный шаг. Не заявлять «всё настроено», если устройством не подтверждено.
